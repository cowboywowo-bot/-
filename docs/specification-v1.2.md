# 名古屋慢旅手帳 — Mobile-first 網站建置規格書 V1.2

> 文件定位：供前端工程師、Codex 或網站建置工具直接執行的 **建置輸入規格（Implementation-ready PRD）**。本文件只規劃網站，不代表網站已建置。  
> 資料依據：使用者提供《名古屋.pptx》及後續修正；資料檔：`nagoya_trip_v1_2_seed.json`。  
> 專案日期：**2026/11/01（日）～2026/11/06（五）**；顯示語言：繁體中文；主要旅遊時區：**Asia/Tokyo**。

## 1. 產品目標與範圍

### 1.1 核心目標

- 手機旅途中 **3 秒內找到今日行程、下一站及導航**。
- 把原 PPT 的六天行程、去回程航班、住宿、景點、餐廳及參考影片整理為單一網站。
- 日系療癒旅行手帳感，**配色靈感來自《ゆるキャン△》的戶外自然氛圍**，不可直接套用受版權保護的動畫角色、Logo、截圖作為網站素材。
- 所有點擊、收藏、勾選、切換都具有清楚反饋；避免多餘動畫。

### 1.2 專案交付形態

- 手機優先之響應式網站（建議 PWA 可加入手機主畫面），主要支援 360～430 px 手機寬度，平板與桌面不破版。
- 初版 **靜態內容 + 瀏覽器本機狀態儲存**；不要求註冊登入、雲端同步、付費 API 或後端服務。
- PWA 的安裝與離線能力須依部署環境支援；**不要把離線地圖、即時天氣、即時列車資訊當成已實現功能**。
- 主要網址可作靜態部署；詳頁網址需支援重整與直接進入（設定 SPA fallback 或框架對應 routing）。

### 1.3 非首版項目（不得偷做成虛假的即時資訊）

實時天氣、航班動態、地鐵班次、多人同步、雲端附件、護照／QR Code 儲存、餐廳即時訂位、以 GPS 自動判定到達景點、即時路徑 ETA。需明確標記「未串接／後續版本」。

## 2. 資訊架構與路由

底部 **固定五分頁**，所有主分頁圖示需有文字：

| Tab | 路由 | 主要內容 | 第一屏最重要 CTA |
|---|---|---|---|
| 首頁 | `/` | 旅程倒數／今日行程／下一站／快捷資訊 | 查看下一站、回飯店 |
| 行程 | `/itinerary` | 11/01～11/06 六日切換與時間軸 | 日期切換、景點詳情 |
| 地圖 | `/map` | 按日期篩選景點、飯店、餐廳；有確認定位者顯示地圖點 | 前往地點、搜尋位置 |
| 美食 | `/food` | 已排行程餐廳、備用料理類別、參考影片及收藏 | 看餐廳、收藏 |
| 旅程 | `/trip` | 航班、飯店、入境教學、旅途清單及重要資訊 | 飯店導航、複製地址 |

其餘次級頁面：

- `/itinerary/:date`：特定日期，支援 `YYYY-MM-DD`，無效日期顯示安全的提示並回到行程。
- `/place/:id`：景點／店家詳情，從行程、地圖、美食共用一個詳情卡／頁面。
- `/resources`：交通、通關、影片、景點參考資料的彙整；由「旅程」入口開啟，不占底部 Tab。
- `/favorites`：個人收藏；由首頁或美食頁進入，不占 Tab。
- `not-found`：友善的 404 錯誤畫面。

## 3. 手機 UI 結構

### 3.1 全站 Layout

- 最上方：小型網站 Logo / 名稱「名古屋慢旅手帳」＋右側目前日期／設定入口；不使用大型常駐導覽列。
- 主要內容：單欄、卡片化，左右安全留白 16 px；大畫面可中央限定 max-width 520～620 px（模擬旅遊手帳手機版）。
- 底部：五個固定 Tab；須考慮 iPhone safe-area，內容尾端加足夠 padding，不能被導航欄遮住。
- 可操作區域：最小 44×44 px，主要 CTA 建議 48 px 高。
- 中／日文並存；日文餐廳名稱不截斷成不可辨識的短字。

### 3.2 首頁 `/`

區塊順序：

1. Hero：`名古屋慢旅日記`、2026/11/01～11/06、插畫感天空／小山／雲朵原創裝飾（不要套用動畫角色）。
2. 日期狀態：旅前顯示倒數；旅中顯示 `Day N` 與當日主題；旅後顯示完整旅程回顧入口。
3. 今日摘要：優先顯示下一個尚未完成的行程項，帶時間、地點、重要註記。
4. 今日完整時間軸：預設 2～3 筆摘要，可點擊「查看全部」。
5. 四個快捷卡：`今日行程`、`前往下一站`、`住宿資訊`、`收藏清單`。
6. 旅途資訊提醒：只顯示有依據、必要的提醒，例如 11/2 10:00 大倉庫入場與 11/6 13:00 抵達機場。

日期判定：旅途「今天」以 **日本 `Asia/Tokyo` 日期** 判定；非旅遊期間，預設顯示下一個待旅行日（旅前為 11/01，旅後可顯示總覽），使用者仍可手動選日。不得混用台灣當日日期與日本時間。

### 3.3 行程 `/itinerary`

- 頂部橫向六日日期 chip（11/01～11/06）、選中的日期具明顯背景色／底線／微動畫。
- 每日時間軸的順序 **完全依 seed 中 events 陣列**，不可憑時間空白而自行改排。
- 每項卡片：類別圖示、時間（若沒有就標「上午／下午／晚餐」或不顯示時間，不能擅自補時刻）、名稱、簡短說明、導航／資料入口、收藏與完成操作。
- 11/02 10:00 吉卜力大倉庫顯示特殊「指定入場時刻」資訊卡；**不要渲染為已購票**。
- 顯示時間狀態：`confirmed_by_user`、`source_flight`、`estimate`、`planned`；UI 簡化中文如「已確認時間」、「航班表定」、「預估」、「行程安排」。
- 行程完成 checkbox 僅改變使用者個人紀錄，不改動 seed，不代表預訂成功。
- 可展開影片、詳細資訊、參考連結；未有該欄位時隱藏按鈕，不能放無效 CTA。

### 3.4 地圖 `/map`

- 上方六日篩選＋全區／景點／餐廳／飯店分類。
- **地點有已驗證座標** 才畫 marker；只有可靠 `mapsUrl` 則提供 `在 Google Maps 開啟`；其餘採「地圖搜尋此地點」且明確標示為搜尋結果，不假裝定位已驗證。
- 顯示可用的地點列表與卡片；外開地圖使用 `target=_blank` + `rel=noopener noreferrer` 或手機深連結安全回退。
- 固定「回飯店」快捷鍵，使用 seed 內的飯店 mapsUrl。
- 若實際導入 MapLibre/Leaflet/Google Maps SDK，必須具備合法圖磚／API 設定；**初版允許用完整地點列表加外部地圖導航達成實用功能**，不可宣稱「實時導航已串接」。

### 3.5 美食 `/food`

- 分頁或篩選：`行程晚餐`、`想吃清單`、`料理種類`。
- `行程晚餐`：依日期呈現 PPT 五晚已排餐廳；訂位狀態預設 **尚未確認**，不顯示「已預訂」。
- `料理種類`：味噌豬排、鰻魚飯、手羽先、味噌烏龍、居酒屋烤串、海鮮居酒屋、炸蝦三明治、咖啡廳、熱壓吐司、各類拉麵、雞蛋沾麵等。
- PPT 第 10～13 頁很多是「料理主題 + YouTube 影片」，**不可自動當成已找到的具體店家或把影片封面當成合法商用照片**。
- 收藏與「吃過」為不同狀態；點擊收藏需即時更新並顯示 Toast。
- 未確認確切位置者顯示 `搜尋地點`，不能生成錯誤地址或假距離。

### 3.6 旅程 `/trip`

- 去程航班 CX530：`11/1 TPE 12:00（台灣時間） → NGO 15:35（日本時間）`。
- 回程航班 CX531：`11/6 NGO 16:40（日本時間） → TPE 19:10（台灣時間）`。
- 11/01 預估 18:00 抵達飯店、11/06 10:00 退房、13:00 到達機場，清楚標示類型。
- 飯店：VESSEL INN SAKAE STATION；顯示中英日地址原文、官方網站、Google Maps、`複製地址`。
- 參考：入境 QR Code 教學、通關影片、吉卜力官網與交通資訊，外部連結採「參考資料」，網站不會生成或儲存官方 QR Code。
- 旅前檢查清單預設可編輯：護照、機票、飯店確認、吉卜力票券確認、eSIM / 網路、交通／現金。**清單完成標記不等於已核驗票證**。
- 不收集護照號碼、個人 QR Code、信用卡、訂房代碼等敏感個資到公開靜態 JSON 或 analytics。

## 4. 視覺設計 Tokens

### 4.1 主題色（色票為本專案的原創定義）

| Token | 色碼 | 用途 |
|---|---|---|
| `--bg` | `#F9F6EC` | 奶油白，全站底色 |
| `--sky` | `#8DC9D9` | Hero、今日資訊、小範圍藍色強調 |
| `--leaf` | `#A8D2B4` | 日期選取、完成狀態、自然系卡片 |
| `--accent` | `#F3BA7A` | 主要 CTA、暖色提示 |
| `--sakura` | `#E9B9BD` | 低頻裝飾與友善提示 |
| `--ink` | `#334D56` | 深色文字，實作需確認 AA 對比 |
| `--subtext` | `#52636A` | 次要文字 |
| `--card` | `#FFFFFF` | 浮起卡片背景 |

主 CTA 若使用暖橘底，文字需選用符合 WCAG AA 對比的深色；狀態不得只用色彩辨識。禁止滿版高飽和塊、閃爍、視差或持續飄動干擾旅遊資訊。

### 4.2 字體與基礎尺寸

- 字體：`Noto Sans TC` 或系統繁體中文無襯線；日文 fallback `Noto Sans JP` / system-ui，不阻塞初始載入。
- 內文 16 px；補充 13～14 px（仍確保可讀）；頁標題 22～26 px；卡片標題 17～19 px。
- 基礎 spacing 4 / 8 / 12 / 16 / 24 / 32 px；卡片圓角 16～24 px；小型 pill 9999 px。
- 陰影淡化；圖片比例優先 16:9（橫幅）、4:3（景點與食物卡）。
- 圖片載入保留固定比例骨架、防止累積位移。

## 5. 互動與狀態規格（必須真實可操作）

| 元件／動作 | 行為 | 回饋與無障礙 |
|---|---|---|
| Tab 切換 | 切換五個路由，保留可用狀態 | 底色／圖示變化 150～220 ms；ARIA current |
| 日期切換 | 載入選定 date 的 events | 200～260 ms 淡入／位移；同步網址 |
| 詳情卡 | 從底部打開資訊面板或詳頁 | 出現／退出 180～260 ms，可點遮罩與返回關閉 |
| 收藏 | 切換 liked 狀態、寫入 localStorage | 圖示填色微縮放、`已加入／已取消收藏` Toast |
| 已走訪／已吃過 | 切換 progress，寫入 localStorage | 勾選反饋＋卡片淡化，但文字仍可閱讀 |
| 複製地址 | 使用 Clipboard API；失敗時手動選字 | 明確顯示「已複製／複製失敗」 |
| 地圖導航 | 開啟可信的地圖 URL 或地點搜尋 | 明確標明「開啟 Google Maps」而非「開始導航」 |
| 外部參考影片 | 開啟 HTTPS 來源 | 可辨識外部連結圖示 |
| 離線 | 已快取的 app shell 與種子資料仍可讀 | 顯示「離線中；地圖／影片需網路」而非空白 |
| 載入失敗 | 重試或顯示替代 UI | 不使用永不結束的 spinner |

- 所有動畫遵循 `prefers-reduced-motion`；減少動態時改為瞬時切換。
- 手機滑動切換日期僅為輔助，不得強制占用原生捲動；提供日期按鈕。
- `localStorage` 建議 key 加前綴 `nagoya-v1.2:`，欄位 `favorites`、`progress`、`checklist`、`notes`，解析錯誤須回退預設值。
- 日期與進度不能用「目前是日本幾點」自動標註已完成；完成是使用者勾選的結果。

## 6. 資料設計與權威性

種子檔案：`nagoya_trip_v1_2_seed.json`，包含 `metadata / flights / accommodation / days / places / foodCandidates / resources / flags / privacy`。

### 6.1 核心關係

- `Trip` 1→6 `Day`；每個 Day 1→N `Event`；Event 可參考 `placeId`。
- `Place` 記錄 ID、分類、官方網址、已知地址、mapsUrl、可能的座標，以及位置是否已核驗。
- `FoodCandidate` 可以是**料理類別**而非店家，絕不可從影片標題推導虛構的餐廳資訊。
- `Resource` 記錄外部參考來源（官網、影片、文章）。
- `timeStatus` 有 `user_confirmed`、`source_flight`、`estimate`、`planned`；畫面顯示與底層資料一一對應，不得混淆。
- `bookingStatus` 若值 `unknown`，UI 不可顯示已購票、已訂位。

### 6.2 不具備資料時的處理

- 無詳細地址：顯示地區或提供 Maps 地點搜尋，不顯示假地址。
- 無照片：顯示原創的風格化 placeholder，不抓取未授權照片。
- 無開始時刻：顯示大致時段／原行程次序，不推算精確時間。
- 無可信票券 URL：顯示「查看官方網站」，不顯示假 QR Code。
- 參考連結失效：有「無法開啟參考連結」提示，不影響主網站使用。
- 明治村→犬山城、熱田神宮→晚餐等 **交通距離與營業時間仍待外部核對**；排程只按原 PPT 保留。

## 8. 建議前端技術與目錄

### 8.1 預設技術決策（開發者可用等效框架替換）

- Vite + React + TypeScript。
- Tailwind CSS 或 CSS variables＋元件 scoped styles；保留上述 tokens。
- React Router 路由，React state + localStorage 儲存輕量互動狀態。
- `lucide-react` 圖示；Icon 一定搭配文字或 aria-label。

## 9. 分階段工作項目

### Milestone A｜可用的首版 MVP（優先）

- 初始化專案＋路由＋主題 tokens＋固定底部分頁。

## 10. 驗收條件（Given / When / Then）

1. **旅程日期**：在日本日期 2026-11-02 開啟首頁，顯示 `Day 2／吉卜力公園`；第一優先的固定入場項為 `10:00 吉卜力大倉庫`。
2. **航班時區**：去程顯示 `TPE 12:00` 到 `NGO 15:35`，回程顯示 `NGO 16:40` 到 `TPE 19:10`，並標示出發／抵達的當地時間，不能自行加減時差到錯誤時間。
3. **11/01 飯店**：首頁與行程均顯示「**預估** 18:00 抵達」，不是已確認的確切到店時間。
4. **11/06 機場**：應有 `13:00 抵達機場` 和 `16:40 CX531 起飛` 兩筆不同事件，不能合併。
5. **無票券假狀態**：吉卜力卡不得出現「已購票」、「開啟入園 QR」等無證據狀態。
6. **旅程資訊**：飯店導航使用資料中的已知 Maps URL；複製地址可以成功，失敗有提示。
7. **底部導航**：五個 Tab 皆可進入對應頁面；進入詳情返回原日期與卷動位置，且 iPhone 安全區不被遮擋。
8. **互動持久化**：收藏一個景點、勾選一項行程後重整網頁，狀態保留；清除站點資料後回復預設。
9. **未知資料誠實呈現**：餐廳訂位未知則寫「訂位未確認」，地址未知時只提供查詢，不會呈現虛構街道或行程交通時間。
10. **離線保底**：離線時已快取的行程和飯店地址仍可查看；外部地圖與影片需網路的提示明確。
11. **無障礙**：鍵盤可移動主要控制；有焦點外框；動態偏好設為減少時停止非必要動畫；文字顏色實測達 WCAG AA。
12. **效能**：圖像有 lazy-loading／明確寬高與 fallback；網頁在 360 px 沒有橫向捲動、卡片和底欄遮擋、或無限 loading。
